# When Codex becomes necessary for GwenTable

## Decision at v0.25.1

Local chat development can still deliver **isolated, working source changes** to core rules modules, CLI tests, static builds, source integrity and zip/patch artifacts. It cannot validly certify the complete browser experience, mobile accessibility, live service-worker upgrade or source-of-truth production integration. **The next integrated release-gate sprint should move into Codex (or an equivalent unrestricted, repository-backed development environment).** Do this before calling G1 PASS or attempting public publication. It is not necessary to stop this local mechanical work prematurely.

## Why the environment change matters

1. **Source of truth**: Import the latest verified ZIP into the real version-controlled repository. Preserve history, verify a clean base, review diffs and merges, run CI and manage branches rather than iterating detached archives.
2. **Actual browser test access**: Launch a functional Chromium/Firefox/WebKit environment that can navigate the running development server. Verify UI rendering, IndexedDB, tabs, service workers, file downloads, PDF popup behavior, accessibility and mobile touch. Repeated browser attempts in the chat sandbox have not yielded validated interactive browser results.
3. **Integration evidence**: Enable automated Playwright E2E checks with screenshots/traces and realistic complete-character test fixtures. Drive against the deployed local/staging build, not just isolated Node DOM mocks.
4. **Advanced level 13–20 progression**: Only Fighter currently has complete level-range authorization (`levelsFor`). Other classes are capped at 12. The class-specific feat/ASI, spell preparation, subclass and high-level character-builder dependencies need a multi-file integration branch with reproducible scenario tests and real UI QA, not blanket lifting of the cap.
5. **Deployment and security**: Use connected hosting, actual environment variables, HTTPS, CSP, release provenance, recovery procedures, staging, logs and post-deployment checks. These are not available by creating detached local ZIPs alone.
6. **Asset ownership**: Codex cannot magically grant copyrights. The owner must still approve, replace or remove the 12 uncleared local assets; a passing preview binary audit is not enough to approve full publication.

## Precise transfer trigger

**Transfer now for the next end-to-end integration/acceptance sprint**, particularly if the immediate goal is a publishable website, full level 20 support or trusted user-facing QA. Further bounded rule-engine increments can continue offline in this chat, but they cannot honestly unblock G1 or establish public-release readiness.

## Required handoff to Codex

Attach `GwenTable_Source_v0.25.1_Local_Development.zip`, implementation patch, `GwenTable_v0.25.1_Development_Handoff.md`, `docs/LOCAL_QA_v0.25.1.md`, original PRD and publication prompt. Verify SHA-256 and 414+ regression tests in the actual environment, then link the real Git remote, run Chromium browser and mobile accessibility tests, and record a formal signed GO/NO-GO. Do not deploy the original artwork or label the system G1 PASS without evidence.
