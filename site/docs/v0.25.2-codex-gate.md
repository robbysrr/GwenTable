# GwenTable v0.25.2: Codex transfer decision

**Codex or an equivalent repository-backed browser-capable development workspace is now REQUIRED for the next integration/release sprint.** Not required for more isolated local Node-verified mechanics. The limitation is verification and delivery, not a claim that these rules cannot be coded here.

## Why

* The only current canonical source is a sequence of detached local ZIP archives. The next integrated release needs a real Git remote, version history, code review, CI and changes that can be deployed and rolled back.
* Actual Chromium/browser E2E, IndexedDB multi-tab transaction behavior, service-worker lifecycle, PDF/popup handling, mobile touch and screen-reader acceptance have not passed in this chat environment. None of the 430 Node tests can certify those interactions.
* Full level-13–20 spellcaster classes require coordinated spell tables, subclass features, feat and slot dependencies plus real UI flows. Removing the class cap without those is not acceptable.
* Publication requires live staging, HTTP security headers, HTTPS, monitoring/rollback, and owner-controlled release rights. Twelve inherited artwork files remain uncleared. No AI coding environment can invent publication licenses or sign off on behalf of the owner.

## Exact trigger

Transfer **before** the next end-to-end integration gate, full level-20 all-classes claim or production/staging publication decision. Continued bounded local rule modules can be built here only as testable handoff candidates. If Codex cannot access a real browser, live repository, or staging environment, use one that can; a workspace name by itself does not remove the gate.

## Codex acceptance order

1. Import `GwenTable_Source_v0.25.2_Local_Development.zip` as the baseline and verify source SHA-256 manifest, source patch, `npm test` (430+) and `npm run build` in the actual worktree.
2. Create or link canonical repository, commit with reviewable diff and run CI. No undocumented replacement of existing data, code or art.
3. Run unrestricted Playwright browser desktop/mobile tests for level-20 Rogue and all earlier workflows. Capture traces/screen reader/keyboard findings and fix actual failures.
4. Complete other classes 13–20 with source-traced rules, generated character validation, and UI tests, one class at a time.
5. Resolve artwork owners' licenses or keep a rights-cleared alternative build; then staging, security, rollback, evidence review and owner GO/NO-GO.

G1 status remains REPAIR. Public production remains NO GO.
