# GwenTable v0.25.3: Codex environment gate and handoff

**Decision:** Local rules development is still possible here. For the **next reliable integration, browser acceptance and publication sprint**, transfer v0.25.3 into a Codex/work environment with actual Git repository access, working browser automation (Playwright/Chromium), responsive/mobile emulation, accessibility audits, staging host access, and permission to record test artifacts. The *capabilities*, not the Codex brand name alone, are mandatory. A Codex session without working browser/network access will not solve the blockers.

**Why now:** Consecutive source-only increments have reproduced automated tests and static HTML but have not established G1 real-browser acceptance. Continuing to grow game features without validating real IndexedDB transactions, browser saves, input behavior, focus, PDF/GCX downloads, mobile interactions and offline updates increases integration risk. Private artwork approval is independent of test environment.

**Baseline package:** `GwenTable_Source_v0.25.3_Local_Development.zip` (complete), with optional `GwenTable_v0.25.3_Source_Changes.patch` against v0.25.2, development handoff and unexecuted local QA guide. Source integrity is checked with `SOURCE_SHA256.json`.

**First Codex steps:** (1) import to a canonical Git branch and preserve all older version history; (2) run `npm test`, `npm run build`, `npm run verify:source`; (3) run end-to-end Chromium/WebKit/mobile tests on the same released source; (4) record actual defects and fix them with tests; (5) verify cross-tab revision collision, IndexedDB persistence, print/PDF, GCX, backups, keyboard and screen-reader flows; (6) retest original asset audit and maintain separate artwork-withheld preview; (7) only then plan remaining 9 classes through level 20 and public staging.

**Gate:** G1 REPAIR / production NO GO. The source package is **not** a deployment approval. Never invent test results, license rights, domain changes, or publication signoff.
