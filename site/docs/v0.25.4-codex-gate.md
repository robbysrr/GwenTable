# GwenTable v0.25.4: Codex environment decision

**Technical decision:** Individual rules modules and local Node regression tests can still be developed in this chat. For the **next trustworthy integration, browser-acceptance and publication sprint**, move to Codex or an equivalent repository-backed development environment that actually has the following capabilities:

- Canonical Git branch/history for the complete v0.25.4 source, repeatable CI, PR review and actual diff provenance.
- Real Chromium/Firefox/WebKit browser tests on localhost, functioning IndexedDB (save/reload/multi-tab conflicts), service worker and caching, real download/PDF/GCX tests, mobile viewport/keyboard/screen-reader checks and captured evidence.
- Staging hosting/deployment, HTTPS, security/privacy and actual rollback testing before production consideration.

**Why mandatory for integration now:** Four classes (Fighter, Rogue, Barbarian, Monk) now have level-20 builder paths, while eight others remain capped at 12. The addition of persistent combat features and offline modules has increased the number of untested browser interactions. Detached ZIP/Node tests cannot prove browser behavior or real user acceptance. Continuing further rules expansion without integration QA would accumulate release risk.

A Codex workspace that lacks repository access, unrestricted browser execution or staging is **not sufficient** merely by being called Codex. Clearing artwork licenses is a separate owner's task. The original 12 files remain unapproved for publication; the artwork-withheld preview is QA-only. Transfer all source and release evidence; reproduce the 459 tests before changing anything.

**Release decision: G1 REPAIR, PUBLIC NO GO.**
