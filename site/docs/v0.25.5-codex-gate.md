# GwenTable v0.25.5: Codex environment boundary

**Technical decision:** Local pure SRD rules and Node tests can still be written here. For the **next complete integration/browser-acceptance/publication sprint**, use Codex or an equivalent workspace that actually provides all of:

1. A canonical Git repository with committed v0.25.5 baseline, CI runs and reviewable PR changes rather than detached ZIP-only history.
2. Functional real browsers for end-to-end checks (Chrome/Chromium, Firefox, Safari/WebKit as accessible) with IndexedDB, two tabs, service worker/offline cache, mobile viewports, keyboard and assistive-tech acceptance, and real character exports/PDF/GCX file roundtrips.
3. A private staging environment with HTTPS, security and privacy audit, release/rollback rehearsal and owner signoff. Never deploy the original 12 uncleared artwork assets publicly. The separate image-withheld preview is still QA-only.

**Why this is mandatory now:** Five high-level classes and a deep Play-state/export system increase integration complexity. Node tests cannot verify interaction, browser persistence, a PDF download initiated after an asynchronous authorization check, or accessibility. The same browser gate has been unverified across several earlier local increments. Further rules-engine development is possible here, but it **cannot** make publication-ready quality claims. A Codex workspace without browser/repository/staging access would not solve the problem; provision these capabilities first.

**Suggested move:** Import v0.25.5 ZIP to a private Git branch, verify all 476 tests and manifest, establish automated browser tests and staging, repair observed defects, then extend the remaining seven classes through 20. Do not self-authorize public release. **Gate G1 REPAIR, PUBLIC NO GO.**
